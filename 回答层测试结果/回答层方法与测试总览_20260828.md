# LLM 证据筛选、回答生成与引用约束层

## 1. 层级边界

回答层只读取检索层的 `RetrievalResponse`，不修改索引和检索排序。入口为 `AnswerEngine.answer(AnswerRequest)`，输出 `AnswerResponse`。

```text
RetrievalResponse
  → EvidenceNormalizer
  → EvidenceBudgeter
  → RetrievalEvidenceSelector（当前默认）
  → EvidenceBudgeter
  → LLMAnswerGenerator
  → CitationValidator
  → AnswerRenderer
  → AnswerResponse
```

当前 Studio 默认通过阿里云百炼 OpenAI 兼容接口调用 `qwen-plus`。API Key 由界面或 `DASHSCOPE_API_KEY` 环境变量提供，不写入诊断日志。原有 Ollama 客户端仍作为可替换适配器保留；Embedding 模型不被当作生成模型使用。

## 2. 证据规范化与预算

检索命中的 `evidence_blocks` 被去重、稳定排序并映射为 `E001`、`E002` 等本次回答内的证据编号。每条证据保留：

- `record_id`、`document_id` 和 `source_block_ids`；
- `modality`、`role` 和 `relation`；
- 原始内容、上下文和视觉资产路径；
- `source_path`、文档类型、页码/幻灯片/工作表及 bbox；
- 检索排名、原始分和融合分。

默认先从检索结果中按命中排名、角色和模态保留最多 18 条候选，再按 `AnswerRequest` 的条数与字符预算生成最终证据集，并限制单文档和单容器数量。所有检索命中的 `core` 先于 `neighbor/related` 进入预算；问题主体与分类焦点精确命中的核心表格块还会进一步前置，避免高排名扩展块或其他核心块挤掉跨分块的目标记录。针对这类精确分类问题，表格内容只保留分类匹配行，防止相邻类别串入答案。空证据、重复证据和禁用的视觉证据不会进入模型上下文。

## 3. 当前证据选择与结构化生成

Studio 当前默认使用 `RetrievalEvidenceSelector`：已经通过混合检索资格门的有界证据直接交给回答模型，不再用关键词规则否决跨语言证据，也不额外调用一个 LLM 做筛选。该选择器与生成器完全解耦，可替换为 `CoverageEvidenceSelector`、`LLMEvidenceSelector` 或其他实现。

可选的 `LLMEvidenceSelector` 使用 `direct / context / conflict` 支持等级，并要求 `support_quote` 必须能在原证据中逐字核验；未知证据编号、低分或无法核验的摘录不会进入回答。默认直通路径则由生成模型结合问题判断证据是否足够，并由本地校验器约束其引用。

第二阶段生成：

```json
{
  "answerable": true,
  "claims": [
    {"text": "独立事实主张", "evidence_ids": ["E001"]}
  ],
  "limitations": []
}
```

证据内容在系统提示中被标记为不可信数据。模型不得执行证据内指令，不得使用外部知识，也不得创造证据编号。

## 4. 引用硬约束

- `answerable=true` 必须至少有一个主张；
- 每个主张必须引用已选证据；
- 每个主张至少需要一条 `direct` 或 `conflict` 证据；
- 未知证据编号和模型手写的 `[E001]` 标记均判为不合格；
- 校验失败只允许模型修复一次；
- 修复仍不合格时返回 `failed`，不输出模型草稿；
- 模型判定证据不足时返回 `insufficient_evidence`。

最终 Markdown 引用由应用渲染，不直接信任模型文本。

## 5. Studio 接入

Studio“证据回答”页当前提供：

- 输入百炼 API Key 并测试连接；
- 选择百炼模型并配置兼容接口地址；
- 使用当前检索结果生成回答；
- 展示引用来源、位置和模态；
- 可选向支持视觉的模型发送已筛选图片；
- 所有网络调用都在后台线程运行。

## 6. 自动化测试

新增测试覆盖：

- 回答请求、证据、主张、引用和响应契约；
- 证据去重、稳定编号和预算限制；
- 提示注入内容隔离；
- 未知引用忽略与伪造引用拒绝；
- 正常回答、证据不足、一次修复和修复失败；
- 百炼 OpenAI 兼容请求、Bearer Key、模型列表和图片 Data URL；
- Studio 回答及引用显示格式。

截至 2026-09-10，项目全量自动化测试共 149 项通过，覆盖输入、索引、检索、回答、引用、百炼客户端、UI 格式、精确分类表格聚焦与跨分块目标证据优先级。

## 7. 当前百炼验收状态

百炼客户端的 OpenAI 兼容端点、鉴权头、模型列表、JSON Object 响应、schema envelope、字符串布尔值和图片 Data URL 已通过 7 项隔离自动化测试。测试使用模拟 HTTP 响应，不消耗真实 API 额度。真实验收入口已更新为当前默认的检索证据直通流程：

```powershell
.build-env\Scripts\python.exe tools\run_answering_acceptance.py --model qwen-plus
```

需要通过 `DASHSCOPE_API_KEY` 或 `--api-key` 提供凭据；凭据不会写入输出。
