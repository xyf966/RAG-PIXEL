# LLM 证据筛选、回答生成与引用约束层

## 1. 层级边界

回答层只读取检索层的 `RetrievalResponse`，不修改索引和检索排序。入口为 `AnswerEngine.answer(AnswerRequest)`，输出 `AnswerResponse`。

```text
RetrievalResponse
  → EvidenceNormalizer
  → EvidenceBudgeter
  → LLMEvidenceSelector
  → LLMAnswerGenerator
  → CitationValidator
  → AnswerRenderer
  → AnswerResponse
```

Ollama 只通过本机 HTTP API 接入。模型名称和服务地址可配置，Embedding 模型不被当作生成模型使用。

## 2. 证据规范化与预算

检索命中的 `evidence_blocks` 被去重、稳定排序并映射为 `E001`、`E002` 等本次回答内的证据编号。每条证据保留：

- `record_id`、`document_id` 和 `source_block_ids`；
- `modality`、`role` 和 `relation`；
- 原始内容、上下文和视觉资产路径；
- `source_path`、文档类型、页码/幻灯片/工作表及 bbox；
- 检索排名、原始分和融合分。

默认最多向筛选器提供 6 条、合计约 10000 字符的证据，并限制单文档和单容器数量。所有检索命中的 `core` 先于 `neighbor/related` 进入预算；问题主体与分类焦点精确命中的核心表格块还会进一步前置，避免高排名扩展块或其他核心块挤掉跨分块的目标记录。针对这类精确分类问题，表格内容只保留分类匹配行，防止相邻类别串入答案。空证据、重复证据和禁用的视觉证据不会进入模型上下文。

## 3. 分阶段结构化模型调用

第一阶段仅判断每条证据的相关性和支持等级：`direct / context / weak / conflict / none`。默认分数阈值为 `0.55`，只有 `direct`、`context` 和 `conflict` 可以进入回答候选。

`direct` 表示证据能够支持答案中的至少一条局部事实，不要求单条证据完整回答整个问题。若首轮只有 `context`，系统会追加一次支持性复核。若仍无 `direct/conflict`，系统最多再复核 5 条排名靠前的文字/表格证据；只有返回可在原证据中逐字匹配、且有效长度不少于 4 个紧凑字符的 `support_quote`，才恢复为 `direct`。仍未恢复时在生成前返回证据不足。

第二阶段生成：

```json
{
  "answerable": true,
  "claims": [
    {"text": "独立事实主张", "evidence_ids": ["E001"]}
  ],
  "limitations": []
}
```

证据内容在系统提示中被标记为不可信数据。模型不得执行证据内指令，不得使用外部知识，也不得创造证据编号。

## 4. 引用硬约束

- `answerable=true` 必须至少有一个主张；
- 每个主张必须引用已选证据；
- 每个主张至少需要一条 `direct` 或 `conflict` 证据；
- 未知证据编号和模型手写的 `[E001]` 标记均判为不合格；
- 校验失败只允许模型修复一次；
- 修复仍不合格时返回 `failed`，不输出模型草稿；
- 模型判定证据不足时返回 `insufficient_evidence`。

最终 Markdown 引用由应用渲染，不直接信任模型文本。

## 5. Studio 接入

Studio 新增“证据回答”页：

- 检测并选择 Ollama 模型；
- 配置 Ollama 服务地址；
- 使用当前检索结果生成回答；
- 展示引用来源、位置和模态；
- 可选向支持视觉的模型发送已筛选图片；
- 所有 Ollama 调用都在后台线程运行。

## 6. 自动化测试

新增测试覆盖：

- 回答请求、证据、主张、引用和响应契约；
- 证据去重、稳定编号和预算限制；
- 提示注入内容隔离；
- 未知引用忽略与伪造引用拒绝；
- 正常回答、证据不足、一次修复和修复失败；
- Studio 回答及引用显示格式。

截至 2026-09-07，项目全量自动化测试共 142 项通过，覆盖输入、索引、检索、回答、引用、UI 格式、精确分类表格聚焦与跨分块目标证据优先级。

- CPU 环境总耗时约 96 秒。

另外使用真实项目索引验证问题“CTCC中国汽车场地职业联赛的无形资产使用有什么”：系统选中两个跨分块核心表格记录，输出“CTCC围场内品牌产品销售”与“CTCC车辆数据支持”，分别引用 `E001`、`E002`；最终状态为 `answered`，无 warnings，8B 单次回答约 96 秒。

`qwen3:8b` 的 Ollama 请求设置 `think=false`，避免证据筛选阶段产生不必要的长思考。`qwen3:1.7b` 不作为默认回答模型。

可使用以下命令复现；项目默认使用 `qwen3:8b`：

```powershell
.build-env\Scripts\python.exe tools\run_answering_acceptance.py --model qwen3:8b
```

退出码为 0 表示模型生成了至少一个通过引用校验的主张。
