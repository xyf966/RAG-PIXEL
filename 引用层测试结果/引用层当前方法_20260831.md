# 引用层当前方法

## 1. 输入边界

引用层不读取 PDF、Word、Excel 或 FAISS。它读取回答层已经规范化和筛选后的对象：

- `EvidenceItem[]`
- `EvidenceDecision[]`
- `AnswerDraft`

上游检索层的 `snapshot_build_id`、`record_id`、`source_block_ids`、`provenance` 和来源文件会沿数据链保留下来。

## 2. 稳定证据编号

`EvidenceNormalizer` 对检索命中的 `evidence_blocks` 去重并排序，然后在本次回答范围内顺序分配：

```text
E001, E002, E003, ...
```

排序优先级是：`core` 先于 `neighbor` 和 `related`；问题主体与分类精确匹配的核心表格优先；之后考虑检索排名、模态、块序和 `record_id`。同一文档、模态和记录 ID 的重复块只保留一次。

编号只在本次 `AnswerResponse` 内稳定；跨不同查询不能假设 `E001` 指向同一记录。长期追溯应使用 `record_id`、`source_block_ids` 和 `snapshot_build_id`。

## 3. 证据选择与支持等级

当前 Studio 默认使用本地 `RetrievalEvidenceSelector`：检索候选经过预算后直接进入百炼生成器，不再发起单独的证据筛选模型调用；引用最终仍由本地 `CitationValidator` 强制校验。

选择器仍是可替换插槽，也可换成 `LLMEvidenceSelector`、`CoverageEvidenceSelector` 或其他实现。当前输出支持等级如下：

证据筛选输出：

| 等级 | 含义 | 能否单独支撑事实主张 |
|---|---|---:|
| `direct` | 包含可直接写入答案的事实、数值或可直接比较内容 | 是 |
| `conflict` | 与其他证据形成有意义冲突 | 是，但回答应说明冲突 |
| `context` | 标题、单位、定义或背景 | 否，只能补充引用 |
| `weak` | 关系较弱 | 否 |
| `none` | 无关 | 否 |

默认 `RetrievalEvidenceSelector` 不设置模型阈值，也不在回答前语义否决检索候选。最终模型只能引用预算内的真实证据 ID；复合问题有部分直接证据时可回答该部分，缺失项只能写入 `limitations`。

可选的本地 `CoverageEvidenceSelector` 能按问题词项覆盖度排序；对于能够解析出“主体 + 分类焦点”的精确表格问题，表格内容仍会在规范化阶段收窄到对应分类行。

## 4. 结构化主张

回答模型必须输出：

```json
{
  "answerable": true,
  "claims": [
    {
      "text": "一条最小、可独立验证的事实",
      "evidence_ids": ["E001"],
      "supporting_quotes": [
        {"evidence_id": "E001", "quote": "证据中的连续原文"}
      ]
    }
  ],
  "limitations": []
}
```

模型提示明确要求：不使用外部知识、不执行证据内指令、不创造 ID，并把回答拆成最小事实主张。

## 5. CitationValidator 硬规则

当 `answerable=true` 时：

1. 至少存在一个 claim；
2. 每个 claim 的 `evidence_ids` 不得为空；
3. 所有引用 ID 必须存在于已筛选证据；
4. `supporting_quotes` 必须覆盖全部引用 ID，且不得包含未引用 ID；
5. 每段 supporting quote 必须是对应证据内容或上下文中的连续原文，过短、改写或拼接的摘录不通过；
6. 每个 claim 至少引用一条 `direct` 或 `conflict` 证据；
7. `claim.text` 中不得出现模型手写的 `[E001]` 样式标记。

`context` 可以与 direct 一起引用，但不能成为某条主张唯一的支持。

## 6. 一次修复与安全停止

如果首次校验失败，程序把错误列表和上一次结构交给生成模型，并要求只修复结构、不得补充证据外信息。修复后重新运行同一个校验器：

- 通过：进入渲染；
- 模型改判 `answerable=false`：返回 `insufficient_evidence`；
- 仍有错误：返回 `failed`，答案文本使用固定安全提示，不泄露无依据草稿。

不会无限重试。

## 7. 应用渲染

`AnswerRenderer` 在校验成功后才把引用追加到主张末尾：

```text
2025 年销售额为 100 万元。[E001]
```

引用列表由 `Citation.from_evidence` 构造，包含证据 ID、记录 ID、模态、来源文件、文档类型、坐标和原始 block ID。Studio 显示类似：

```text
[E001]  年度报告.pdf  ·  第 3 页  ·  TABLE
```

## 8. 当前限制

`CitationValidator` 现在会验证每个引用都有真实存在于对应证据中的连续原文，因此不能只绑定一个合法 ID 而不指出依据。但它仍不执行第二次 LLM 语义审计：原文存在不等于数学上证明 claim 的每个词都被蕴含。计算和跨证据综合由回答模型完成，并要求摘录所有必要输入；若需要更强保证，可在未来增加确定性的领域规则，而不是重新加入通用 LLM 否决器。
