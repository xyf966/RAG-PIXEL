## 引用相关覆盖

### 编号和来源

- 证据块去重并稳定分配 `E001…`；
- 所有核心块优先于 related/neighbor；
- 精确主体和分类匹配的目标表格优先；
- Citation 从 EvidenceItem 构造并保留页码和 block ID；
- 嵌套内容和 provenance 防御性复制。

### 模型输出约束

- 提示注入内容被标记为不可信数据；
- 模型返回未知证据 ID 时被忽略或拒绝；
- `answerable=true` 但没有主张会失败；
- 引用数组不能为空；
- 仅有 context 证据时不能生成事实答案；
- claim 文本中的手写 `[E001]` 被拒绝。

### 修复与失败策略

- 合法引用直接生成 `answered`；
- 伪造 `E999` 后允许一次修复；
- 第二次仍引用 `E999` 时返回 `failed`；
- 筛选后没有证据时返回 `insufficient_evidence`；
- 默认选择器不会以关键词规则否决跨语言检索证据；
- 可选 LLM 选择器的 `support_quote` 不能在原证据中逐字核验时不会提升支持等级；
- 选择后无 direct/conflict，或生成器判断证据不足时，在生成前或生成后安全拒答。

### Studio 展示

- 引用标签显示 ID、来源文件、位置和模态；
- 回答状态、limitations 和 warnings 可见。

## 测试边界

单元测试使用可控的结构化模型响应，证明百炼协议适配、校验器和失败路径正确。它不证明任意生成模型都会提供正确事实；当前仍保留历史 Ollama 真实验收记录，百炼还需要使用用户自己的 API Key 做真实验收，并在未来增加 claim–evidence 语义蕴含评估。
