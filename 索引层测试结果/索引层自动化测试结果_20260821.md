## 文字分块测试

已验证：

1. 标题路径、页码边界、重叠窗口和稳定 record ID 得到保留；
2. 超长正文遵守 768 token 硬上限，并使用重叠窗口继续拆分；
3. 分块不会跨越页面、幻灯片、工作表或标题路径；
4. 原始块 ID 与每个来源块的 provenance 可回溯。

## 表格分块测试

已验证：

1. 长表拆分时重复表头；
2. 宽表拆分时保留第一列并拆分其余列；
3. Excel 原生键值表不会把第一行误当成表头；
4. PDF 表格中的跨列表标题行不会被误当成普通 header；
5. 转义竖线和超长单元格不会丢失，并遵守 token 上限；
6. 无法结构化的表格明确进入 `raw` 后备，而不是伪造矩阵；
7. 原生 cells、结构化 table_cells、合并范围、公式与来源位置得到保留。

## 视觉契约与物化测试

已验证：

1. PDF visual 只在索引阶段按 bbox 裁切；
2. Office 原生对象导出优先于页面裁切；
3. Office 导出不可用时，允许策略可按已识别页面区域后备；
4. 严格 Office 策略会拒绝缺失的原生导出；
5. 没有 visual 的 Office 文档不会无意义启动 COM；
6. `kind=text/table` 与 `indexable=false` 的 visual 不会进入 Pixel；
7. 未知 `visual_type`、空 block ID 和重复 block ID 会被拒绝；
8. Pixel 零向量在写入索引前被拒绝；
9. Pixel 首次漏回结果时自动重试一次；
10. 纯白、纯黑、过小占位图和透明底问题经过质量门处理；
11. 重复图片共享一次 embedding，但保留两条可追溯记录。

## 快照与完整性测试

已验证：

1. 快照始终包含 text、table、visual 三个有效 FAISS 和 metadata；
2. `CURRENT` 正确指向已发布快照；
3. 源文件发布后被修改时，当前快照校验失败；
4. 快照内视觉图片被修改时，SHA-256 校验失败；
5. 无效 visual 会记录警告，不阻止另外两个有效的空索引生成；
6. 新构建失败后，旧 `CURRENT` 保持不变；
7. schema 1.x 旧索引会提示重建；
8. Office visual 快照若未使用严格 COM/native 策略，会被读取端拒绝。

## 输入层回归测试

索引改造后，原有 21 项输入层测试仍全部通过，覆盖：

- 文件签名、bundle 往返和 schema 1.1；
- OpenDataLoader PDF 与 PyMuPDF 回退；
- openpyxl XLSX 与 Docling 回退；
- Word/PPT/Excel 原生视觉对象；
- 坐标补全与图片上下文；
- 图片仅停在 visual 契约，不在识别阶段向量化；
- PixelRAG session 常驻复用。

## 测试结论边界

自动化测试大量使用 `FakeSession` 和小型临时文件，证明的是控制流、契约、分块和失败保护逻辑正确。真实模型加载、Office COM 和复杂文件表现由[真实文件测试结果](./索引层真实文件测试结果_20260821.md)单独验证。
